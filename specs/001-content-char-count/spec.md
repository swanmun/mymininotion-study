# Feature Specification: 글 내용 글자 수 표시

**Feature Branch**: `001-content-char-count`

**Created**: 2026-10-01

**Status**: Draft

**Input**: User description: "내용입력칸 아래에다가 내용을 입력하면 글자 수 계산하는 기능을 만들거야."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 입력하는 동안 글자 수 확인 (Priority: P1)

사용자는 글 상세 화면의 내용 입력칸에 글을 쓰면서, 입력칸 바로 아래에서 지금까지 쓴 글자 수(공백 포함)를
바로 확인합니다. 글자를 넣거나 지우면 숫자가 그 즉시 바뀝니다. 이미 내용이 있는 글을 열면 처음부터 그 글의
글자 수가 보입니다.

**Why this priority**: 요청의 핵심 기능입니다. 이것만 있어도 "얼마나 썼는지"를 바로 알 수 있습니다.

**Independent Test**: 글 상세 화면에서 내용 입력칸에 글자를 입력·삭제하면서 입력칸 아래 숫자가 바뀌는지
확인하면 됩니다.

**Acceptance Scenarios**:

1. **Given** 내용이 비어 있는 글을 열었을 때, **When** 화면이 표시되면, **Then** 입력칸 아래에 글자 수 0이 보입니다.
2. **Given** 내용이 비어 있는 글에서, **When** "안녕 하세요"를 입력하면, **Then** 글자 수가 6으로 보입니다 (공백 1자 포함).
3. **Given** 글자 수가 6인 상태에서, **When** 마지막 글자 1개를 지우면, **Then** 글자 수가 5로 바뀝니다.
4. **Given** 내용이 "회의 메모"(5자)로 저장된 글이 있을 때, **When** 그 글을 열면, **Then** 입력 없이도 글자 수 5가 보입니다.
5. **Given** 다른 글로 이동했을 때, **When** 새 글이 열리면, **Then** 글자 수는 이전 글이 아니라 새 글의 내용 기준으로 보입니다.

---

### User Story 2 - 공백을 뺀 글자 수 확인 (Priority: P2)

사용자는 띄어쓰기·줄바꿈을 뺀 순수 글자 수도 함께 확인합니다. 제출용 글처럼 "공백 제외" 기준이 필요한 경우에
따로 세지 않아도 됩니다.

**Why this priority**: 한국어 글쓰기에서 자주 쓰는 기준이지만, 공백 포함 글자 수만으로도 기본 목적은 달성됩니다.

**Independent Test**: 공백과 줄바꿈이 섞인 내용을 입력하고, 공백 제외 숫자가 공백 포함 숫자와 다르게 맞게
계산되는지 확인하면 됩니다.

**Acceptance Scenarios**:

1. **Given** 내용이 비어 있는 글에서, **When** "안녕 하세요"를 입력하면, **Then** 공백 제외 글자 수가 5로 보입니다.
2. **Given** 내용이 비어 있는 글에서, **When** "가 나"를 입력하고 줄을 바꾼 뒤 "다"를 입력하면, **Then** 공백 포함 5, 공백 제외 3으로 보입니다.
3. **Given** 내용에 공백만 3개 입력했을 때, **When** 숫자를 보면, **Then** 공백 포함 3, 공백 제외 0으로 보입니다.

---

### Edge Cases

- 이모지·결합 문자(예: 피부색이 들어간 이모지, 국기)는 사람이 보기에 한 글자이면 1자로 셉니다.
- 한글 완성형 글자(예: "한")는 자모로 쪼개지 않고 1자로 셉니다.
- 줄바꿈은 공백 포함 글자 수에서 1자, 공백 제외 글자 수에서 0자로 셉니다. 탭도 공백으로 취급합니다.
- 내용을 한 번에 붙여 넣거나 전부 지워도 숫자는 바로 맞게 바뀝니다.
- 1,000자 이상이면 세 자리마다 쉼표를 넣어 표시합니다 (예: 1,234).
- 제목은 글자 수에 포함하지 않습니다.
- 글이 없거나 찾을 수 없는 화면에서는 글자 수를 표시하지 않습니다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 글 상세 화면은 내용 입력칸 바로 아래에 내용의 글자 수를 표시해야 합니다 (MUST).
- **FR-002**: 글자 수는 사용자가 입력·삭제·붙여 넣기를 할 때마다 즉시 갱신되어야 하며, 자동 저장 완료를 기다리지 않아야 합니다 (MUST).
- **FR-003**: 글자 수는 사람이 보기에 한 글자인 단위로 세야 합니다. 한글 완성형 글자와 이모지는 각각 1자입니다 (MUST).
- **FR-004**: 시스템은 공백 포함 글자 수와 공백 제외 글자 수(띄어쓰기·줄바꿈·탭 제외)를 함께 표시해야 합니다 (MUST).
- **FR-005**: 글을 열었을 때 저장된 내용 기준의 글자 수를 처음부터 표시해야 합니다 (MUST).
- **FR-006**: 제목은 글자 수 계산에 포함하지 않아야 합니다 (MUST).
- **FR-007**: 1,000 이상의 숫자는 세 자리마다 쉼표로 구분하고, 자릿수가 바뀌어도 숫자 폭이 흔들리지 않게 표시해야 합니다 (MUST).
- **FR-008**: 글자 수 표시는 기존 화면 디자인 규칙(작업형 화면, 메타 정보 크기의 보조 글자, 존댓말 없는 짧은 라벨 · 가운뎃점 구분)을 따라야 합니다 (MUST).
- **FR-009**: 글자 수 표시는 보조 기술(스크린 리더)이 읽을 수 있는 텍스트여야 하며, 입력할 때마다 소리 내어 알리지는 않아야 합니다 (SHOULD).
- **FR-010**: 글자 수 기능은 글 저장·자동 저장·삭제 등 기존 동작을 바꾸지 않아야 합니다 (MUST).

### Key Entities

- **글 내용(Page content)**: 기존 글의 본문 텍스트입니다. 글자 수는 이 텍스트에서 매번 계산하는 값이며 따로 저장하지 않습니다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 글자를 입력하거나 지운 뒤, 화면에 보이는 글자 수가 같은 순간(눈에 띄는 지연 없이) 바뀝니다.
- **SC-002**: 한글·영문·숫자·공백·줄바꿈·이모지가 섞인 시험 문장 10개에서 표시된 두 숫자가 손으로 센 값과 10개 모두 일치합니다.
- **SC-003**: 10,000자 분량의 내용을 붙여 넣어도 입력이 끊기거나 느려지지 않고 숫자가 바로 맞게 표시됩니다.
- **SC-004**: 글을 열 때마다 별도 조작 없이 첫 화면에서 글자 수를 확인할 수 있습니다 (조작 0회).
- **SC-005**: 기능 추가 전후로 글 저장·자동 저장·삭제 동작의 결과가 달라지지 않습니다 (기존 동작 회귀 0건).

## Assumptions

- "글자 수"의 기본 기준은 공백 포함이며, 한국어 글쓰기 관례에 따라 공백 제외 글자 수도 함께 보여 줍니다.
- 표시 형식은 "글자 수 1,234 · 공백 제외 1,000"처럼 한 줄의 짧은 라벨과 숫자입니다. 정확한 문구·배치는 디자인 가이드에 맞춰 계획 단계에서 정합니다.
- 최대 글자 수 제한이나 경고는 이번 범위에 넣지 않습니다.
- 단어 수, 문단 수, 읽는 시간 같은 다른 통계는 이번 범위에 넣지 않습니다.
- 글자 수는 저장하지 않으므로 데이터 구조나 저장 방식은 바뀌지 않습니다.
- 대상 화면은 기존 글 상세 화면 하나이며, 사이드바 글 목록에는 글자 수를 표시하지 않습니다.
